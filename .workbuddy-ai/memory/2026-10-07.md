## 二、JNI 重命名回归修复（本次复查发现）
- 包名 sed 只替换了点号形式，漏掉 JNI 符号的下划线形式：`app/src/main/cpp/native-lib.cpp:42` 仍为 `Java_com_omarea_vtools_SceneJNI_getKernelPropLong`，
  而 Java 类已迁到 `com.yuanshiguang.nekoscene.SceneJNI`，会导致首次调用 `getKernelPropLong`（`CpuFrequencyUtils.java:37`）抛 `UnsatisfiedLinkError`。
- 已改为 `Java_com_yuanshiguang_nekoscene_SceneJNI_getKernelPropLong`。全仓仅此一处下划线残留。

## 三、CI 构建失败修复（NDK 版本不匹配）
- 现象：`gradle assembleRelease` 在 Configure project :app 失败，`No version of NDK matched the requested version 23.1.7779620`，runner 自带 27/29/30。依赖解析已正常（jcenter 修复生效）。
- 根因：`.github/workflows/android.yml` 与 `Scene5.yml` 都用 `nttld/setup-ndk@v1` 装 r23b，但该 action 把 NDK 装到**非 SDK 标准目录**；`app/build.gradle:75` 写死 `ndkVersion '23.1.7779620'`，AGP 只在 `$ANDROID_SDK_ROOT/ndk/<版本>` 按版本号找 → 找不到。
- 修复：两处工作流改为用 SDK 自带 `sdkmanager` 安装 `ndk;23.1.7779620`，使其落在标准目录；同时 checkout/upload-artifact 升 v4、setup-java distribution 改 temurin；android.yml 的 Deploy 指向**上游** helloklf/vtools-dev-apks 且依赖 secrets.ACCESS_TOKEN，在自己 fork 上会失败，已设 `continue-on-error: true` 并注释提示改 GITHUB_REPO。
- 校验：两个 yml 通过 pyyaml 解析；全仓已无 `setup-ndk`/`ndk-version`/`ANDROID_NDK_HOME` 残留。
